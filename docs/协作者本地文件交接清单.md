# 协作者本地文件交接清单

协作者从 GitHub 克隆代码后，不应直接接收整个项目目录。只需根据运行方式补齐以下内容。

## 必须自行创建或安全获取

1. 根目录 `.env`
   - 从仓库中的 `.env.example` 复制后修改。
   - API Key、数据库密码等真实密钥应由各自账号申请；确需共用时，通过团队认可的密钥管理或加密渠道传递，不要通过 GitHub、普通聊天记录或邮件明文发送。
   - `DATABASE_URL` 中的本地绝对路径必须改成协作者电脑上的项目路径。

2. `resources/data/` 下的五个初始化 Excel
   - `表结构DEV.xlsx`
   - `枚举值DEV.xlsx`
   - `业务知识DEV.xlsx`
   - `历史SQLDEV.xlsx`
   - `表关系DEV.xlsx`
   - 仅在确认协作者有权访问其中业务元数据后，通过安全渠道发送。

## 根据运行方式选择

3. `data/dev.sqlite`
   - 使用当前 SQLite 示例业务库时需要发送。
   - 如果协作者连接自己的 MySQL/其他业务库，则不需要发送，只需修改 `.env`。

4. `data/auth/users.json` 和 `data/auth/user_workspaces.json`
   - 推荐协作者分别复制仓库中的 `users.example.json`、`user_workspaces.example.json`，再设置自己的本地密码。
   - 只有确实需要完全相同的测试账号时才私下发送现有文件；其中密码当前以明文保存，应按敏感文件处理。

## 不需要发送

- `.venv/`：协作者按 `requirements.txt` 重新创建。
- `web/node_modules/`：在 `web` 目录执行 `npm install` 或 `npm ci` 重建。
- `web/.angular/`、`web/dist/`：缓存和构建产物可重新生成。
- `resources/cache/`：模型与向量化缓存可重新生成。
- `logs/`、`*.log`、`*.sse`、`*.jsonl`、`*.pid`：本地运行和调试文件。
- `__pycache__/`、`*.pyc`：Python 自动生成文件。

## 克隆后的最短准备流程

```powershell
Copy-Item .env.example .env
Copy-Item data\auth\users.example.json data\auth\users.json
Copy-Item data\auth\user_workspaces.example.json data\auth\user_workspaces.json
python -m venv .venv
.\.venv\Scripts\python.exe -m pip install -r requirements.txt
cd web
npm.cmd ci
```

补齐 `.env`、初始化 Excel 和可选 SQLite 后，再根据 README 启动依赖服务并运行初始化脚本。
